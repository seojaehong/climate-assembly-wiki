# 의제 원문 페이지 재구성 검토

작성일: 2026-06-25

## 결론

현재 `content/ko/agenda/*.md`는 공신력 있는 의제 원문 DB가 아니라 내부 가안 브리프다. 그래프의 "의제 원문 보기" 링크가 이 문서로 연결되는 것은 표현상 과장이다. 실제 의제 페이지는 `Supabase DB + 경기도 기후도민회의 OCR 자료`를 원천으로 재구성하고, 내부 가안은 "해설 초안" 또는 "작업 메모"로 격하해야 한다.

## 현재 구조의 문제

1. 원문과 해설이 섞여 있다.
   - "한 줄 요약", "왜 중요한가", "쟁점", "En-ROADS", "시민 FAQ", "관련 세션"이 한 페이지에 섞여 있다.
   - 시민/모더레이터가 보기에 "이 의제가 공식적으로 어디서 왔는가"가 먼저 보이지 않는다.

2. 출처 위계가 뒤집혀 있다.
   - 현재 페이지는 내부 작성 문서를 source of truth처럼 보이게 한다.
   - 실제 원천이어야 할 자료는 경기도 OCR 문서, 공식 결과보고서, Supabase 적재 코퍼스, 해외사례 DB다.

3. "원문 보기"라는 UI 문구가 부정확하다.
   - 현재 연결 대상은 원문이 아니라 내부 가공 브리프다.
   - 그래프 카드에서는 "내부 의제 해설 보기" 또는 "관련 의제 자료 보기"로 낮춰야 한다.

4. 페이지가 의사결정 보조 화면으로 작동하지 않는다.
   - 의제 상태, 선정 단계, 채택 여부, 원문 발췌, OCR 페이지, 유사 해외사례, 관련 시민 발언이 분리되어 있지 않다.
   - 그래서 읽어도 "무엇을 확인해야 하는지"가 명확하지 않다.

## 확인된 실제 원천 후보

### 경기도 기후도민회의 OCR

로컬 원천 위치:

- `00_입력자료/경기도 기후도민회의/evaluation/json/*.pages.json`
- `00_입력자료/경기도 기후도민회의/evaluation/text/*.txt`
- `00_입력자료/경기도 기후도민회의/evaluation/ocr_documents/md/*.md`
- `10_작업산출물/2026-06-22_경기의제_검토본.md`

검토본 기준으로 확인된 의제 원천:

- 2차 상세제안: 84건
- 3차 채택판정: 71건
- 성과보고 최종선정: 20건
- 워킹그룹: 기후격차, 기후경제, 에너지전환, 소비와자원순환, 도시생태계

### Supabase

현재 함수/테이블 흐름:

- `kb_chunks`: RAG 지식베이스 chunk
- `agenda_corpus`: 캔버스 의제 코퍼스
- `build-kb`: `{ source, items:[{ ref_id, doc, title, body, category, meta }] }` 적재
- `kb-search`: `match_kb` 검색
- `build-corpus`, `corpus-search`, `agenda-knn`: 의제 유사도/검색 계열

현재 `supabase/migrations/README.md`는 신규 graph/analysis 테이블을 이연한다고 명시한다. 따라서 v1 페이지는 신규 스키마 변경 없이 edge function 또는 정적 export JSON으로 시작하는 것이 안전하다.

## 새 페이지 정보 구조 제안

의제 페이지는 다음 6구역으로 재구성한다.

1. 의제 식별
   - 공식/자료상 제목
   - 출처 구분: 경기도 OCR, 공식 결과보고서, 시민 발의, 해외사례, 내부 해설
   - 상태: 2차 상세제안, 3차 채택, 미채택, 최종선정, 참고사례
   - 워킹그룹/분과/날짜

2. 원문 발췌
   - OCR 원문 그대로
   - 문서명, 페이지, ref_id
   - OCR 신뢰 상태: 텍스트층, OCR, 수동 검수 필요

3. 쉬운 요약
   - 3~5문장 요약
   - "이 요약은 원문을 대체하지 않음" 표시

4. 숙의 쟁점
   - 주장
   - 근거
   - 우려/소수의견
   - 조건
   - 하버마스 온톨로지 그래프와 연결되는 역할

5. 비교 자료
   - 경기도 유사 의제
   - 2026 기후시민회의 관련 의제
   - 해외 시민회의 유사 권고/의제
   - Supabase 검색 결과 또는 정적 export 결과

6. 내부 해설
   - 기존 `content/ko/agenda/*.md`의 내용은 이 구역으로 이동
   - 제목은 "내부 작업 해설" 또는 "모더레이터 참고 초안"
   - 공식 원문으로 오해되지 않게 표시

## 그래프 카드 문구 수정 방향

현재:

- "의제 원문 보기"

권장:

- v1 정적 가안 연결 상태: "내부 의제 해설 보기"
- 경기도 OCR 연결 후: "경기도 의제 원문 보기"
- Supabase 통합 후: "관련 자료 보기"

카드 고지 문구:

> 관련 가능성이 높은 자료입니다. AI가 결론을 만든 것이 아니며, 원문과 출처를 확인하기 위한 숙의 보조 링크입니다.

## 구현 순서

1. 현재 그래프 카드 문구를 즉시 낮춘다.
   - `의제 원문 보기` → `내부 의제 해설 보기`
   - section title도 `관련 의제 위키` → `관련 의제 자료`

2. 경기도 OCR 기반 정적 export를 만든다.
   - 입력: `evaluation/json/*.pages.json`, `2026-06-22_경기의제_검토본.md`
   - 출력: `public/workshop-graph/data/gyeonggi-agenda-surface.json`
   - 필드: `id`, `title`, `stage`, `working_group`, `status`, `source_doc`, `page_refs`, `original_excerpt`, `summary`, `keywords`

3. 의제 페이지 라우트를 분리한다.
   - 내부 가안: `/ko/agenda/{slug}/`
   - 실제 자료: `/ko/agenda-source/{source}/{id}/`
   - 그래프 카드는 우선 실제 자료 라우트로 연결한다.

4. Supabase 어댑터를 붙인다.
   - 신규 DB schema 변경 없이 `kb-search` 또는 전용 read-only edge function으로 시작
   - 응답 shape는 정적 JSON과 동일하게 유지

5. 해외사례 DB를 같은 surface에 통합한다.
   - "해외 시민회의 유사 의제/권고" 섹션에만 노출
   - 국내 의제 원문과 같은 층위로 섞지 않는다.

## 다음 작업 권고

바로 구현한다면 1단계는 작고 안전하다. 카드 문구를 낮추고, 기존 내부 가안 페이지 상단에 "내부 작업 해설 초안" 배지를 넣는다.

그 다음 2단계에서 경기도 OCR export를 만들어야 한다. 이때부터 현재 가짜 DB가 아니라 실제 source-backed 의제 자료 페이지가 된다.
