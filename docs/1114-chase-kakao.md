# 11/14 투표 진행판 + 카톡 독려 전송 — 운영 절차

운영 PC(본컴)에서만 돈다. 운영 사이트 배포 없이 로컬 서버 하나(`127.0.0.1`)가 화면과 카톡 전송을 맡는다.

- 진행판: 권고안별 투표율(그 건을 누른 인원 / 출석 인원), 분과·조별 제출·진행·미시작, 이름별 「n/총건」
- 카톡 독려: 미제출자 문구를 만들어 스태프 단톡방에 보낸다(수동 또는 N분마다 자동)
- 찬반은 어디에도 나오지 않는다. 진행 기록은 「그 건을 눌렀다」만 담는다(16:30 일괄 공개 전)

## 0. 체크 인원 정의(11/12 결정)

- **대상** = 의결 서명자 가운데 그 의제 투표지에 [제출]을 안 누른 사람. 의제 1·2·3 따로 센다.
- **의결 서명자** = 현장 마감 명부(서재홍 님이 마감 처리해 한글 파일로 줌)에 있는 사람. 진행판 「의결 서명 명단」 칸에 한 줄 한 명(`조|이름` 또는 이름)으로 넣고 [서명 명단 저장].
  - 넣으면 분모 = 서명 인원(머리줄 「제출 n / 의결 서명 m」), 서명 안 한 명단 사람은 ①② 에서 빠진다.
  - 비워 두면 명단 전원 기준(「제출 n / 명단 m」).
  - 명단(조·이름)에 안 맞는 줄은 칸 옆에 「명단에 안 맞는 줄」로 뜬다 — 오타·조 표기를 고친다.
- **① 투표 중 미제출** — 카드를 눌렀는데 [제출] 안 함. 「이름 n/총건」. 찾아가 [제출]을 돕는다.
- **② 미시작** — 서명했는데 투표지를 안 엶. QR 접속·자리 확인.
- **③ 이름 확인** — 독려가 아니라 현장 확인.
  - 기기 2대 이상: 한 이름이 여러 폰에서 쓰였다. 도움을 받아 진행요원 폰으로 이어 하는 중이면 정상. 아니면 남이 그 이름으로 들어간 것일 수 있다.
  - 명단 밖 이름: 직접 입력한 이름(오타·조 착오).
  - 의결 서명 명단에 없음: 서명 안 한 사람이 제출했다(마감 뒤 도착자 등). 제출 수에 넣지 않는다.
- **수기 투표** — 수기 투표지를 받아 진행요원이 **대리 입력 모드**로 넣는다(아래). 따로 제외하지 않는다.
- **그 밖 제외** — 의결권 없는 사람이 명단에 있으면 「그 밖 제외」 칸에.

### 대리 입력 모드(진행요원 폰)

- 주소 = 그 의제 QR 주소 끝에 `&proxy=1` 을 붙인다(예 `https://climate-assembly.org/b?t=…&proxy=1`). 오른쪽 위에 「대리 입력」 표시.
- 조·이름 → 카드 → [제출] → 완료 화면의 **[다음 사람 입력]** → 다음 사람. 사람마다 새 기기로 처리돼 한 폰으로 여러 명을 넣을 수 있다.
- 본인 폰에서 하다가 진행요원 폰으로 넘겨도 된다(1번 카드부터 다시). 먼저 [제출]한 쪽만 들어가고, 나중 기기는 「이미 이 이름으로 제출」로 막힌다.
- 대리 입력으로 들어간 표는 진행판 ③ 에 「대리 입력으로 제출됨」으로 남아(기기 2대 이상일 때) 수기 투표지와 대조할 수 있다.
- 일반 QR 주소(끝에 `&proxy=1` 없음)로는 한 폰에서 한 번만 제출된다.

## 1. 미리 할 일

1. **s34 마이그레이션 적용 확인** — `ballot_progress_board` 가 운영 DB에 있어야 「진행 중 n/총건」과 권고안별 누른 인원이 나온다.
   없으면 진행판이 노란 띠(「진행 기록 함수(s34)가 아직 운영 DB에 없습니다」)를 띄우고 **제출한 사람만** 센다. 이때 진행 중 건수는 0 으로 보인다.
2. **운영자 접속 토큰** — `/mod` 에 로그인한 노트북 개발자 도구에서
   `JSON.parse(localStorage.climate_vote_mod_session_v1).accessToken` (64자리).
   파일 한 줄로 저장해 `--token-file` 로 주거나 환경 변수 `CV_ACCESS_TOKEN` 에 넣는다. 화면·로그·명령 줄에 그대로 쓰지 않는다.
   토큰 파일은 저장소 밖(예: `%USERPROFILE%\cv_token.txt`)에 둔다.
3. **스태프 단톡방 등록(사용자 몫, 11/13 방 생성 후)**
   ```powershell
   & $readerPython -I -B -m room_links link --room '스태프 단톡방 정확한 이름' --folder '<작업폴더>' --create
   & $readerPython -I -B -m native_setup --room '<고정 번호>' ...   # kakao-room-work 스킬 절차
   & $readerPython -I -B -m room_links show --room '스태프 단톡방 정확한 이름'   # 고정 번호 확인
   ```
   여기서 나온 방 번호를 `--room` 에 준다. 방이 정해지기 전에는 `--room` 없이 띄운다(보내기 단추가 꺼지고 「스태프 단톡방 미등록」 표시).
4. **본인방 시험** — `--room self-inbox` 로 띄워 한 번 보내 보고 카톡에 실제로 왔는지 눈으로 본다.

## 3. 진행판 보는 법(3~5초)

- **위 막대** — 투표지 선택, 새로고침 3초/5초(기본 3초), **출석(서명) 인원**(모수, 기본 = 명단 수, 이 PC 에 기억), **마감 시각**(HH:MM, 문구 머리줄 「남은 시간 n분」에 쓴다), 마지막 갱신 시각.
- **큰 숫자** — 제출 · 제출률(출석 기준) · 진행 중 · 미시작 · 제외.
- **권고안별 투표율** — 번호 · 제목 앞부분 · 「누른 인원 / 출석」 · %. 50% 미만은 노란 %. 명단 밖 이름 때문에 100%를 넘으면 100%로 자른다.
- **분과·조별 진행** — 조를 누르면 이름이 펼쳐진다. 노랑 = 진행 중(n/총건), 빨강 = 미시작, 초록 = 제출, 회색 줄 = 제외.
- 맨 아래 「명단 밖 이름으로 들어온 사람」 — 직접 입력한 이름. 오타·조 착오일 수 있으니 현장에서 확인.

## 4. 카톡 독려

문구 모양:
```
[의제1 투표 독려] 14:32 기준 · 남은 시간 8분
제출 120 / 명단 174 · 남은 분 50

① 투표 화면에 들어왔는데 아직 제출 안 함 30명 — 찾아가 도와주세요
· 1분과 3조(2): 홍길동 7/19, 김철수 3/19
② 아직 투표 시작 안 함 20명 — 도착·QR 접속 확인
· 1분과 3조(2): 김, 이
```

- **제외(불참·서면)** — 한 줄 한 명, `조|이름`(예 `1분과 3조|홍길동`) 또는 이름만(그 이름 전부). [제외 저장] 하면 `.tmp-chase/settings.json` 에 남아 재시작해도 유지된다.
- **수동 전송** — 미리보기를 고쳐도 된다(고치면 자동 갱신이 멈춘다, [최신 값으로 다시 만들기]로 되돌림). [카톡 보내기]는 **5초 안에 한 번 더** 눌러야 나간다.
- **자동 전송** — 기본 꺼짐. 켤 때 확인 창이 뜬다. 2/3/5분마다 서버가 **그때 새로 읽은 값으로** 문구를 다시 만들어 보낸다(화면의 고친 문구는 쓰지 않는다).
  최신 값을 못 읽었거나, 투표지가 열림이 아니거나, 남은 분이 0이면 건너뛴다.
  - 켜는 시점: 의제 발표가 끝나고 투표 타이머가 돌기 시작한 뒤 2~3분 지나서(처음 1~2분은 대부분 「진행 중」이라 문구가 길기만 하다). 타이머 끝나면 끈다.
- **전송 결과** — 화면에 상태를 그대로 띄운다(`sent_native_recorded` 등).
  `uncertain` 은 「나갔는지 모른다」는 뜻이다. **다시 누르지 말고** 카톡 방을 눈으로 확인한다. 자동 전송은 `uncertain`·실패에서 스스로 꺼진다. 재시도는 하지 않는다.
- 같은 방 · 같은 문구는 같은 요청 키(Idempotency-Key)를 쓴다. 카톡 API 가 같은 키를 한 번만 처리하는지는 실제 API 로 아직 확인하지 않았다 — 두 번 누르지 않는 것을 원칙으로 한다(머리줄 시각이 바뀌면 다른 문구).
- 실제 카톡 API(8755)로는 아직 한 번도 보내 보지 않았다. `room` 값 형식과 발송 응답의 상태 이름은 본인방 시험(1-4)에서 처음 확인한다.

## 5. 테더링 · 끊김

- 진행판은 3초마다 묻고 4초 안에 답이 없으면 그 회차를 버린다(재시도 없음). 끊기면 빨간 띠와 함께 **마지막 정상 값**을 계속 보여 준다. 갱신 시각을 보고 얼마나 묵었는지 판단한다.
- 끊긴 동안 자동 전송은 건너뛴다(묵은 값으로 보내지 않는다).
- 카톡 API 는 로컬(127.0.0.1:8755)이지만 카톡 앱이 실제로 보내려면 인터넷이 필요하다. 끊긴 동안 보내면 실패나 `uncertain` 이 나올 수 있으니 연결이 돌아온 뒤 방을 눈으로 확인하고 보낸다.
- s34 를 서버를 켜 둔 채 적용하면 60초 안에 노란 띠가 사라지고 진행 기록으로 넘어간다(안 넘어가면 서버를 다시 켠다).

## 6. 파일·보안

- `.tmp-chase/` — 제외 목록(`settings.json`) · 전송 기록(`send-log.jsonl`, 상태·코드·글자 수만). 실명이 들어가므로 폴더 안 `.gitignore`(`*`)로 git 밖에 둔다.
- 서버는 `127.0.0.1` 에만 붙고, POST 는 같은 출처(Origin)·JSON 만 받는다. 다른 웹 페이지가 이 주소로 보내지 못한다.
- 카톡 API 토큰: `%LOCALAPPDATA%\kakao-reader\api\token`. 시험용으로 `CHASE_KAKAO_BASE`·`CHASE_KAKAO_TOKEN_FILE` 환경 변수로 바꿀 수 있다.
