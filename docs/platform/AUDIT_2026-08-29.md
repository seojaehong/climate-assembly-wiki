## 🔴 F1. 레거시 `public.cv_*` 뷰 4종 — anon이 전권 DML을 가진다

`cv_votes` · `cv_rounds` · `cv_tally` · `cv_tally_scale`. postgres 소유의 SECURITY DEFINER 뷰라 **조회자의 RLS를 우회**한다.

| | anon SELECT | anon INSERT | anon UPDATE | anon DELETE |
| --- | --- | --- | --- | --- |
| `public.cv_votes` (뷰) | O | O | O | **O** |
| `public.cv_rounds` (뷰) | O | O | O | **O** |
| `climate_vote.votes` (원표) | O(정책) | O(정책) | X | **X** |
| `climate_vote.rounds` (원표) | O(정책) | X | 정책이 차단 | **X** |

원표는 RLS로 잠겨 있는데 **뷰가 그 잠금을 우회한다.** 즉 뷰 4종이 테이블 보호를 무력화하는 옆문이다.

`public.cv_set_active(p_round_id text)`도 같은 계열이다. SECURITY DEFINER · 본문에 인증 검사 없음 · anon EXECUTE. 어떤 회차든 활성화하고 기존 활성 회차를 내린다.

### 권고 — 오늘 하지 않는다

행사 당일에는 손대지 않는다. 8/29 경로가 이 표면을 쓰지 않아 미루는 비용이 0이고, `votes`는 복구 수단이 없다.

행사 종료 후, **마이그레이션 파일로** 처리한다(SQL Editor 즉석 실행 금지 — 추적에서 벗어난다).

```sql
-- 초안. 적용 전 사용자 승인 필요.
revoke all on public.cv_votes, public.cv_rounds,
              public.cv_tally, public.cv_tally_scale from anon, authenticated, public;
revoke all on function public.cv_set_active(text) from anon, authenticated, public;
-- 사용처가 없음을 재확인했다면 뷰 자체를 드롭하는 편이 낫다.
```

☑ 적용 뒤 확인 — **PUBLIC 회수와 역할별 회수를 함께 볼 것.** anon만 회수하면 PUBLIC 경로로 안 닫히고, 반대로 PUBLIC만 회수하면 로그인 사용자만 막히는 사례가 이 프로젝트에 있었다. anon 키와 세션 토큰 두 경로를 각각 시험한다.
