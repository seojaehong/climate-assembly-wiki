# 7/4 현장 톡방에서 도출한 콘솔 요구사항

출처: 모더레이터 운영 단톡방 로그(2026-05-04~07-10). 개인 실명은 옮기지 않는다.
용도: 8/29 대비 기능 우선순위 근거.

## 전제

내부 실시간 확인용이다. **공식 출석 확인은 갤럽이 별도로 수행한다.**
따라서 이 콘솔의 목표는 법적 정확성이 아니라 **본부가 지금 몇 명 있는지 한 화면에서 아는 것**이다.

## 관찰 1 — 출석 집계가 톡방 복붙으로 붕괴했다 (핵심 근거)

10:33~13:07 사이 17개 조 전체 목록을 통째로 복사해 자기 조 한 줄만 고쳐 다시 올리는 메시지가
60건 넘게 오갔다. 관찰된 실패는 다음과 같다.

- **버전 충돌**: 같은 분 단위에 서로 다른 숫자를 담은 목록이 동시에 올라온다.
  (예: 같은 조가 한 메시지에서는 4명, 다른 메시지에서는 8명)
- **되돌아감**: 뒤에 올라온 목록이 앞 목록의 갱신을 누락해 이미 올라간 값이 사라진다.
- **항목 증식**: 없던 `18.`번 줄이 생겨 목록 길이가 조마다 달라진다.
- **운영자 개입 반복**: "해당 조만 확인해서 올려주세요", "다른 조에 업데이트하지 마세요",
  "전체 목록은 여기까지만" 등 진행 통제 메시지가 반복된다.
- **최종 수렴 실패**: 결국 운영자가 직접 종합본을 다시 작성해 올리는 방식으로 마무리된다.

→ `/mod` 조별 입력 + `/hq` 집계가 정확히 이 문제를 없앤다. 이번 개발의 1순위 근거다.

## 관찰 2 — 조가 15개가 아니라 **17개**다

톡방 집계 목록은 1~15번(숙의 3분과 × 5조)에 더해 **16.기획 A조, 17.기획 B조**를 포함한다.
현재 시드(`scripts/seed-0829-lib.mjs`)는 15개만 만든다.

- 기획 A/B조는 인원이 8명·10명으로 숙의조와 다르다.
- 8/29에 기획참여단이 참여하는지 확인이 필요하다. 참여한다면 시드에 2개 조를 추가해야 한다.

**미결 — 사용자 확인 필요.**

## 관찰 3 — 조별 총원이 제각각이다

관찰된 총원: 8, 9, 10, 12명. 시드의 `TEAM_CAPACITY = 20`은 실제와 맞지 않는다.
현재 `hq_teams()`는 명부가 있으면 명부 인원을, 없으면 capacity를 분모로 쓰므로
**명부가 적재된 조는 이미 올바른 분모**를 쓴다. 명부 없는 조만 20으로 표시된다.

## 관찰 4 — 테이블 번호와 조 번호가 다르다

현장 좌석은 1~15번 테이블로 배치되고 분과·조 번호와 일치하지 않는다.
"15번 테이블 = 3분과 4조" 같은 대조가 톡방에서 수동으로 이뤄졌고,
행사 직전 청소년조를 앞으로 옮기며 2분과·3분과의 1조↔5조가 서로 뒤바뀌기도 했다.

→ 조 카드와 명부 화면에 **테이블 번호 병기**가 필요하다. 조 이름만으로는 현장에서 못 찾는다.

## 관찰 5 — 명단에 없는 참여자가 나타난다

명부에 없는 참여자가 다른 조 테이블에 앉아 있었고, "이분 어느 조인가요?"를 톡방에 물어
다른 모더레이터가 찾아주는 방식으로 해결됐다.

→ 자기 조 안에서만 검색되는 현재 구조로는 못 푼다. **본부 화면에서 전체 조 이름 검색**이 필요하다.
(실명을 다루므로 HQ 권한 뒤에 둔다.)

## 관찰 6 — 지각·중도 귀가 시각을 행사 5일 뒤에 기억으로 복원했다

7/9에 운영자가 조별로 "불참자와 조기 귀가자(시각)"를 다시 물어야 했고,
"12시 반~1시쯤", "13시 30분 전으로 기억합니다" 같은 답이 돌아왔다.
늦게 온 사람은 톡방 로그를 뒤져 추정했다.

→ 지각·조퇴 **시각 기록은 이미 구현돼 있다**. 필요한 건 그것을 **사후 보고서 형태로 뽑는 것**이다.
조별 불참자·지각·조퇴를 시각과 함께 한 번에 내보내면 이 왕복이 사라진다.

## 관찰 7 — 조별 배포물 확인이 또 하나의 복붙 라운드였다

설문지·유인물·질문지 배포 확인이 "우리 조 받았습니다 / 못 받았습니다"를 조마다 톡에 올리는
방식으로 진행됐고, 누락 조를 찾는 데 시간이 걸렸다.

→ 본부가 항목을 띄우면 각 조가 한 번 탭해 응답하는 **조별 점호(브로드캐스트 체크)** 가 있으면
같은 패턴을 한 화면으로 대체할 수 있다. 출석 집계와 구조가 같다.

## 관찰 8 — 휴대폰 없는 참여자가 있다

조별로 휴대폰이 없는 참여자가 확인됐다. QR 투표가 불가능하다.

→ **대리 입력은 이미 구현돼 있다.** 리허설 체크리스트에 이 경로를 명시적으로 넣는다.

## 우선순위 제안

| 순위 | 항목 | 근거 |
|---|---|---|
| P0 | 기획 A/B조 포함 여부 확인 후 시드 | 관찰 2 — 조 수가 틀리면 집계가 처음부터 어긋난다 |
| P0 | 조 카드·명부에 테이블 번호 병기 | 관찰 4 — 현장에서 조를 못 찾는다 |
| P1 | 조별 점호(브로드캐스트 체크) | 관찰 7 — 두 번째 복붙 라운드를 없앤다 |
| P1 | 지각·조퇴 시각 포함 사후 내보내기 | 관찰 6 — 5일 뒤 기억 복원을 없앤다 |
| P2 | HQ 전체 이름 검색 | 관찰 5 — 빈도는 낮지만 막히면 오래 막힌다 |

## 하지 않기로 한 것

- **자리 비움 추적**: 화장실 이동까지 공유되자 운영자가 "그것까지 공유 안 해주셔도 됩니다"라고
  정리했다. 상태를 늘리면 입력 부담만 커진다.
- **공식 출석부 대체**: 공식 확인은 갤럽 소관이다. 이 콘솔은 내부 실시간 파악용에 한정한다.
