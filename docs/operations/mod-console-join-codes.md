# 모더레이터 콘솔 조 접속코드 운영

## 책임과 생성 위치

- 책임자: 행사 전 세션을 준비하는 본부 운영 담당자
- 생성 위치: `scripts/seed-0829-teams.mjs`의 Node `crypto.randomInt`
- 조 번호 기준: `scripts/session-rosters.mjs`의 `SESSION_ROSTERS[<세션 슬러그>].teams` (회차별 정의)
  - 회차가 바뀌면 이 파일에 정의 한 항목을 추가하고 `ACTIVE_SESSION_SLUG`만 바꾼다. 코드값을 소스에 적지 않는다.
  - `scripts/seed-0829-lib.mjs`의 `OFFICIAL_TEAM_ROSTER`는 활성 회차 정의에서 파생된 값이다.
- 브라우저 역할: `/mod/`는 코드를 한 번 교환해 짧은 수명의 기기 토큰을 받은 뒤 코드가 아닌 토큰으로만 동작한다. URL·localStorage·오프라인 큐에는 평문 코드를 남기지 않는다.

## 정상 발급 규칙

접속코드는 운영 SQL 패킷을 만들 때 암호학적으로 안전한 난수원으로 생성하는 서로 다른 6자리 값이다. 날짜·조 순번·전화번호처럼 추측 가능한 값을 조합하지 않는다.

- `ordinal`은 화면·명찰·배부표의 조 정렬 기준일 뿐 코드의 일부가 아니다.
- 같은 세션을 다시 출력해도 새 코드 패킷이 만들어진다. 승인한 패킷 하나만 적용한다.
- 과거 `MMDD+순번` 값은 회귀 테스트와 과거 자료 확인용일 뿐 9.12~13 운영에 배포하지 않는다.
- 평문 코드는 승인된 담당자가 봉인된 오프라인 배부표에만 옮기고 로그·채팅·보고서·스크린샷에 남기지 않는다.

코드는 최초 접속을 위한 일회성 부트스트랩 수단이다. 교환 뒤에는 주소창에서 즉시 제거되고, 분실·노출 또는 기기 회수 때 HQ에서 해당 기기 토큰을 폐기하거나 전체 코드를 교체한다.

## 운영 명령

새 세션과 누락 조 생성 계획 확인:

```powershell
node scripts/seed-0829-teams.mjs --dry-run
```

현재 배포 환경의 서비스 역할 키에는 `climate_vote.session`/`team` 직접 권한이 없다. 따라서 아래 명령으로 관리자용 단일 트랜잭션을 출력한 뒤, 출력에 평문 코드가 포함됨을 인지하고 승인된 보안 화면에서만 검토한다. 터미널 기록·CI 로그·일반 파일에 출력을 저장하지 않는다.

```powershell
node scripts/seed-0829-teams.mjs --print-seed-sql
```

이미 존재하는 15개 조의 코드를 새 보안 코드로 일괄 교체하기 위한 관리자용 단일 트랜잭션 출력:

```powershell
node scripts/seed-0829-teams.mjs --print-sync-sql
```

출력된 SQL은 별도 DB 변경 승인을 받은 뒤 Supabase SQL Editor에서 본부 운영 담당자가 실행한다. SQL은 공식 15개 조·기관·세션 경계와 코드 충돌을 먼저 검사하고, 하나의 트랜잭션에서 갱신·검증한다. 검사나 갱신이 실패하면 전체가 롤백된다. 서비스 역할 키에 테이블 권한을 추가하는 방식은 별도 권한 변경 승인을 받은 뒤에만 사용한다.

## 유출·분실 시 재발급

특정 조 코드가 노출됐고 아직 전체 교체 전이라면 보안 난수 코드로 한 조만 재발급할 수 있다.

```powershell
node scripts/rotate-join-code.mjs "1분과 1조" --dry-run
node scripts/rotate-join-code.mjs "1분과 1조" --print-sql
```

`--print-sql`이 만든 단일 트랜잭션은 별도 DB 변경 승인을 받은 뒤 Supabase SQL Editor에서 실행한다. 적용 후 기존 코드로 교환이 거부되고, 새 코드는 지정 조에만 연결되며, 이미 발급된 의심 기기 토큰은 HQ에서 별도로 폐기됐는지 확인한다.
