- 범위: Gate A D2·D3·D4·D5·D6의 외부 운영조건
- 방식: 저장소와 `../10_작업산출물`의 아키텍처 플랜, 사업제품계획서, 개인정보 처리방침 초안, 검수 계약 및 KISA·디지털서비스 이용지원시스템 공식 자료를 읽기 전용 검색·대조

## 근거

### D2·D3 — 인증과 감사 귀속

- `../10_작업산출물/2026-08-09_공론화플랫폼_아키텍처_플랜.md:18`은 HQ 공유비밀의 membership 전환을 Phase 2 선행조건으로 둔다.
- 같은 파일 `42-46`은 현재 HQ 공유비밀·자기신고 actor와 목표 membership 인증을 대조한다.
- 같은 파일 `133-140`은 facilitator를 `join_code (+ 향후 계정)`, operator/HQ/org_admin을 기명 Auth 역할로 구분한다.
- 같은 파일 `300-305`는 진행자 Auth 범위와 플랫폼화 착수를 사용자 결정으로 남긴다.

따라서 D3 방향은 기존 정본으로 확인된다. D2는 facilitator를 영구 제외하는 결정이 아니라 첫 활성화에서 현장 전환을 미루는 단계적 결정으로 기록해야 한다.

### D4 — 승인자 분리

- `docs/platform/ONTOLOGY_REVIEW_QUEUE_CONTRACT.md:21`과 `29-30`은 결정된 검수에 reviewer·timestamp와 append-only event를 요구한다.
- 같은 파일 `62-68`은 한 decision RPC 안에서 membership, compare-and-set, reviewer 불변식을 검사한다.
- 같은 파일 `93-98`은 로컬 reviewed plan이 게시 승인 증거가 아니라고 명시한다.

검색한 정본 범위에서 “2인 승인”, 독립 reviewer 또는 승인 SLA 의무는 발견되지 않았다. 이는 현재 요구사항이 아니라 필요 시 새로 결정할 운영 통제다.

### D5 — managed와 공공조달 트랙

- `../10_작업산출물/2026-08-09_공론화플랫폼_아키텍처_플랜.md:105-110`은 row-level 단일 프로젝트를 권고하되 데이터 소재지 요구 시 database-per-tenant를 재검토한다.
- `../10_작업산출물/2026-08-10_국내공론화SaaS_사업제품계획서.md:17-20`은 managed Supabase가 CSAP 공공 트랙에 맞지 않으며 데이터 분류가 인프라 분기라고 명시한다.
- 같은 파일 `124-133`과 `140-148`은 공공조달 트랙을 CSAP 인증 IaaS 셀프호스트로 분리한다.
- 같은 파일 `168-178`은 데이터 분류와 managed/CSAP 병행 여부를 착수 전 결정으로 둔다.
- `../10_작업산출물/개인정보_처리방침_초안.md:3-6`은 문서가 v0.1이며 KCSC·환경부·법률 검토가 필요하다고 밝힌다.
- [KISA SaaS 보안인증 안내서](https://isms.kisa.or.kr/board/file/bbs_0000000000000004/64/FILE_000000000000915/2023031715564523949363878.pdf)는 SaaS 유형·등급별 통제항목과 인증 유효기간을 안내하지만 특정 제품에 셀프호스트를 일률적으로 요구하는 근거는 아니다.
- [디지털서비스 이용지원시스템의 CSAP 인증 SaaS 사례](https://m.digitalmarket.kr/m/service/detail.do?s=SAS-5-09-11759)는 공공용 public cloud 기반 SaaS가 등록될 수 있음을 보여준다. 이는 managed Supabase의 적격성을 입증하지는 않지만, 공공조달 SaaS가 곧 셀프호스트여야 한다는 단정은 지지하지 않는다.

내부 사업계획의 셀프호스트 분기는 제품 가설로는 유효하지만 공식 규제 결론으로 확인되지 않았다. 따라서 D1의 row-level 논리 격리는 현 비공공 managed 배포와 각 물리 deployment 내부의 기본값으로 한정한다. 공공조달은 별도 CSAP 적합성 검토 트랙으로 기록하고, provider·기반 인프라 적격성과 기관별 물리 격리 요구를 확인한 뒤 managed, 별도 프로젝트 또는 CSAP 적격 IaaS 셀프호스트 중 topology를 결정해야 한다.

### D6 — 고객군과 책임자

- `../10_작업산출물/2026-08-10_국내공론화SaaS_사업제품계획서.md:113-122`는 Phase A 최소 제품 기능을 정의한다.
- 같은 파일 `168-188`은 1차 고객군으로 갈등관리 수행사 화이트라벨을 권고한다.
- `../10_작업산출물/개인정보_처리방침_초안.md:114-121`은 운영 책임자를 운영지원단으로 적지만 개인정보 처리·기술·법률 책임자는 확정 필요 상태다.

따라서 D6의 시장 방향과 non-production 최소 범위는 근거가 있지만 production pilot 실행 책임은 아직 없다.

## 결정 패킷 반영 기준

1. D2는 `facilitator` 영구 제외가 아니라 단계적 후속 전환으로 표현한다.
2. D3는 조건부 목록에서 제거하되 실제 migration/Auth/traffic은 계속 별도 gate로 둔다.
3. D4는 현 계약에 2인 승인이 없음을 명시하고, 필요할 때만 신규 요구사항으로 추가한다.
4. D5는 비공공 managed 운영과 공공 CSAP 적합성 검토를 분리한다. 셀프호스트는 적격성 확인 뒤 선택할 fallback으로 두며 Gate A에서 확정하지 않는다.
5. D6는 수행사 화이트라벨을 1차 고객군으로 기록하되 named pilot·owner가 없으면 production adapter를 차단한다.
