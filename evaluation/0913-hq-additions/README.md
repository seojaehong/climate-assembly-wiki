# 본부 계정 3인 추가 — 실행 대기

- 요청 대상: 한만목, 김상규, 김진우. 기존 기명 HQ 역할, 담당 분과 기본값은 전체.
- 현재 상태: 이번 작업의 운영 데이터 쓰기 0회. SQL Editor 읽기 조회 성공.
- 한만목·김상규: 기존 운영자 및 credential 존재, active=true, default_subgroup=null, must_change_password=true. 기존 비밀번호 값과 실제 로그인은 미검증.
- 김진우: 운영자 및 credential 모두 없음.
- `provision.sql`은 김진우만 추가하도록 축소한 초안이며 운영 실행·로그인 검증은 미완료. SQL Editor에 비밀번호 자리표시자 상태로 준비함.
- 기존 이름 또는 비밀번호 키가 하나라도 있으면 전체 트랜잭션을 중단하므로 기존 계정을 덮어쓰지 않음.
- 실제 비밀번호는 파일·로그·Notion에 기록하지 않음. SQL Editor에서 사용자가 입력·실행 필요.
- 실행 후 각 이름의 HQ 로그인과 전체 15개 조 조회를 검증해야 완료.
- 변경 파일: 이 보고서와 `provision.sql`. 운영 앱 및 스키마 변경 없음.

## 접근 경로 재확인 및 정정

이전 세션 기록에서 운영 작업은 Supabase SQL Editor 경로였음을 확인했습니다. REST 관리 API 403만으로 SQL 권한이 없다고 판단한 것은 잘못입니다. 현재 같은 프로젝트의 SQL Editor를 직접 열면 Supabase 로그인으로 이동하며, GitHub로 계속하기도 GitHub 로그인 화면으로 이동합니다. 현재 확인된 차단점은 브라우저 로그인 세션 부재입니다. SQL 권한 회수 여부는 확인되지 않았습니다. 로그인 화면을 인앱 브라우저에 유지했으며, 계정 추가는 여전히 미실행입니다.
