# 1분과 발표·기록모더레이터 원인 점검

## 반영 내용

- 1분과 송출 순서를 주제 1 → 6 → 3 → 4 → 8 → 7로 우선 배치하고, 이후 나머지 주제와 추가 주제를 표시한다.
- 송출 카드에 권고안 제목뿐 아니라 배경·문제 인식, 기대효과, 권고 내용을 함께 표시한다. 값이 비어 있으면 `작성 중` 또는 `아직 입력되지 않았습니다`로 구분한다.
- 주제·조 선택 결과 표도 동일한 발표 순서를 사용한다.
- 기록모더레이터 상단 안내를 `주제 선택 → 권고안 추가 → 세 항목 입력 → 새 권고안 저장` 순서로 명시했다.

## 원인 분석

- `live-team-access.json` 점검 기록에서 1분과 1조의 `agendaCount`가 0건으로 남아 있다. 로그인 자체는 성공했지만 배정 주제가 없으면 기록 화면에서 작성할 대상을 선택할 수 없다.
- 현재 저장은 자동 저장이 아니라 `+ 권고안 추가`로 카드를 만든 뒤 `새 권고안 저장`을 눌러야 서버에 기록된다. 이 단계가 기존 8/29 자유 입력 화면과 달라 혼동 가능성이 있다.
- 조 화면의 현재 권한/상태가 읽기 전용이면 입력 버튼이 비활성화된다. 화면의 작업단계 확정 상태와 HQ 배정 결과를 먼저 확인해야 한다.
- 실제 운영 로그에는 HQ 3명 모두 9·8·8 주제 조회와 3분과 송출은 통과했지만, 운영 브라우저에서 모든 조의 실제 입력을 검증한 증거는 없다. 따라서 ‘로그인 후 작성이 안 된다’는 신고는 주제 미배정, 저장 단계 미진행, 읽기 전용 중 하나를 현장에서 확인해야 한다.

## 검증

- `npm.cmd run check`: 오류 0건 (기존 프로젝트 경고·힌트만 존재).
- 기존 fixture 자동화는 개발 서버가 실행되지 않은 상태에서 실행되어 화면 대기 시간 초과로 종료되었다. 이 결과를 기능 실패로 해석하지 않고, 서버를 띄운 뒤 브라우저 드라이런을 다시 실행해야 한다.
