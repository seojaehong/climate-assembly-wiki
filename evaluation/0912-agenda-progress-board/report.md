# 9/12 분과 진행상황판 구현 보고서

## 구현 범위

- 1·2·3분과 의제 25건을 `9·8·8`로 분리해 별도 정본 데이터로 추가했다.
- 전체 15개 조를 여러 의제에 배정할 수 있도록 했고, 배정은 HQ만 변경할 수 있다.
- 진행상태는 `대기 → 논의 중 → 초안 작성 → 조 확인 → 제출 완료`의 5단계로 관리한다.
- HQ는 로그인 직후 전체 3개 분과를 보며, 분과별 필터와 독립 송출 화면을 사용할 수 있다.
- 기록모더레이터는 자기 조에 배정된 의제만 보고 진행상태와 공개용 초안을 작성한다.
- 기존 제출·출석·투표·8/29 기록 구조는 변경하지 않고, 새 의제·배정·진행상태 테이블과 RPC를 추가했다.

## 운영 반영

- 기명 HQ 계정 3건을 담당 분과와 함께 활성화했다.
- 초기 자격증명은 운영 DB에 bcrypt 해시로만 저장했으며 코드·Git·로그·Notion에는 평문을 남기지 않았다.
- 운영 DB에 신규 마이그레이션을 적용하고, 의제 25건과 세션 기반 권한·멱등 쓰기·append-only 보호를 검증했다.
- 수신 원본 13건과 중복 정리본 12건은 프로젝트 작업산출물 폴더에 보관했다.

## 설계상 보호장치

- 요청 UUID를 재사용해 네트워크 재시도 시 중복 진행기록이 생기지 않는다.
- 진행상태 갱신은 advisory lock으로 동일 의제의 동시 쓰기를 직렬화한다.
- 배정·의제 수정은 HQ 세션만 가능하고, 조 세션은 자기 조에 배정된 의제만 기록할 수 있다.
- 수정·삭제·truncate 방지 트리거로 기존 진행기록을 덮어쓰지 않는다.
- 브라우저 오프라인 상태에서도 초안을 로컬에 남기고 재접속 후 전송할 수 있다.

## 알려진 로컬 검증 환경 이슈

- 전체 루트 Vitest 묶음은 기존 `decision-vote-console.test.mjs`의 로컬 파서 오류로 완료되지 않았다. 이번 변경과 직접 관련된 85건은 별도로 전부 통과했다.
- 전체 PostgreSQL 검증 스크립트의 신규 마이그레이션·검증 구간과 기존 회귀 구간은 통과했으나, 마지막 기존 CLI seed 구간은 명시적 오류문 없이 종료 코드 1을 반환했다. 신규 DB 범위는 운영 DB에서도 별도로 적용·검증했다.
