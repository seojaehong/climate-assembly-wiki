## 검토한 경계

1. 인증·토큰·ACL·세션 격리
   - 조 접속코드는 한 번 교환한 뒤 URL과 저장소에서 제거하고, 이후 요청은 세션·조에 묶인 토큰만 사용한다.
   - 동시 활성 기기는 조별 2대로 제한하며 폐기·만료·다른 세션·다른 조직의 토큰을 거부한다.
   - P2a는 새 token RPC 권한 부여와 구형 HQ·출석·산출물 RPC 권한 회수를 한 트랜잭션으로 묶는다.
   - 기존 공유 비밀번호 bearer는 전환 시 폐기하고 이름이 있는 HQ 운영자 인증으로 다시 로그인하게 한다.

2. 멱등성·낙관적 동시성 제어·경합
   - 저장, 라운드·투표·본부 제어, 분류·전체 비우기는 UUID 멱등키와 예상 버전·상태·이벤트를 함께 검증한다.
   - 같은 요청의 재시도는 같은 결과를 반환하고, 다른 payload로 멱등키를 재사용하면 거부한다.
   - 활성 라운드 생성, 조별 두 기기 제한, 접속코드 제한, 이름 있는 HQ 인증은 트랜잭션 잠금으로 직렬화했다.
   - 분류 이동·연결 해제는 원본과 대상 snapshot을 한 트랜잭션에서 비교해 전부 반영하거나 전부 취소한다.

3. 감사 로그의 우회 방지
   - P4 post-apply 검증은 감사 테이블·시퀀스가 영속 객체인지, 함수 본문·기본값·제약·인덱스·트리거·ACL이 정확한지 확인한다.
   - 허용되지 않은 추가 BEFORE ROW 트리거와 실행 순서 변경을 거부한다.
   - 임의 로그인 역할의 테이블·컬럼·시퀀스 접근, permissive RLS 정책, `WITH GRANT OPTION`을 모두 거부한다.
   - P4 적용 전후의 기존 workshop·attendance 감사 이력을 canonical JSONB SHA-256과 행 수로 대조한다.

4. 공개 입력 경계와 개인정보
   - `/v`와 `/b`는 익명 공개 입력 경로지만, 브라우저 기기 식별이 강한 신원 확인은 아님을 화면에 명시한다.
   - `/b`는 공식 표결이 아닌 비구속 현장 의견조사로 표시하고 결과를 기기 응답 건수로 표현한다.
   - 공식 의사결정에는 별도의 일회용 ballot capability가 필요하다는 중단 조건을 유지한다.

5. 오프라인·재접속 데이터 보존
   - 오프라인 초안은 토큰·접속코드를 포함하지 않는 큐에 저장하고, 재접속 뒤 같은 request ID와 base version으로 재전송한다.
   - 새 꼭지 개방 시 입력·포커스·스크롤을 보존하고 충돌 시 서버 snapshot을 덮어쓰지 않는다.
   - 구형 초안 이전은 내구 저장을 확인한 뒤에만 접속코드를 제거하며, 실패 시 사용자에게 복구 경로를 보여준다.
   - 서버 로그아웃 실패 시 로컬 capability를 유지해 폐기를 다시 시도할 수 있다.

6. 증거·운영 패킷 무결성
   - release validator는 source commit, ancestor 관계, target revision, releaseRunId, 서명 공개키와 artifact SHA-256을 검증한다.
   - 운영 패킷은 stage에서 전부 검증한 뒤 교체하며 기존 결과를 조용히 덮어쓰지 않는다.
   - 중단 뒤 남은 `.stage`·`.backup`은 수동 삭제하지 않고 SHA와 releaseRunId를 다시 확인하도록 런북에 명시했다.
   - Windows 작업 트리를 WSL Git이 읽을 때 줄바꿈만 변경으로 오인하는 문제를 해소하되 실제 내용 차이는 계속 release 모드에서 차단한다.

## 이번 구현에서 닫힌 주요 결함

- release self-attestation의 fail-open 가능성
- UNLOGGED 감사 객체, 추가 mutation trigger, rogue role·RLS·grant-option 우회
- 토큰 폐기·로그아웃 실패 때 복구 수단까지 지우던 수명주기 문제
- 활성 라운드·기기 제한·공유 HQ 제한의 동시 요청 경합
- 존재하지 않는 이름 반복으로 정상 HQ 로그인을 방해할 수 있던 인증 잠금 경계

- `/v` 공개 정적 페이지의 안전하지 않은 DOM 삽입
- `/b`의 기기 기반 응답을 공식 표결·참여 인원처럼 보이게 하던 문구
- 운영 패킷의 부분 작성·중간 덮어쓰기·증거 교체 위험
- Windows/WSL 줄바꿈 차이로 release 검증이 거짓 실패하던 문제
