## 검토한 경계

1. 인증·토큰·ACL·세션 격리
   - 조 접속코드는 1회 교환 뒤 URL과 저장소에서 제거하고, 이후 요청은 세션·조에 묶인 토큰만 사용한다.
   - 동시 활성 기기는 조별 2대로 제한하고, 폐기·만료·다른 세션·다른 조직의 토큰을 거부한다.
   - P2a 전환은 새 token RPC 권한 부여와 구형 HQ·출석·산출물 RPC 권한 회수를 한 트랜잭션으로 묶는다.
   - 기존 공유 비밀번호 bearer는 전환 시 폐기하고, 이름이 있는 HQ 운영자 인증으로 다시 로그인하도록 했다.

2. 멱등성·낙관적 동시성 제어·경합
   - 저장, 라운드·투표·본부 제어, 분류·전체 비우기는 UUID 멱등키와 예상 버전·상태·이벤트를 함께 검증한다.
   - 같은 요청의 재시도는 같은 결과를 반환하고, 다른 payload로 멱등키를 재사용하면 거부한다.
   - 활성 라운드 생성, 조별 두 기기 제한, 접속코드 throttle, 이름 있는 HQ 인증은 트랜잭션 잠금으로 직렬화했다.
   - 분류 이동·연결 해제는 원본과 대상 snapshot을 한 트랜잭션에서 비교하고 전부 반영하거나 전부 취소한다.

3. 공개 입력 경계와 개인정보
   - `/v`와 `/b`는 익명 공개 입력 경로로 유지하되, 브라우저 기기 식별은 강한 신원 확인이 아니라는 점을 화면에 명시했다.
   - `/b`는 공식 표결이 아닌 비구속 현장 의견조사로 표시하고 결과를 `기기 응답 n건`으로 표현한다 (`src/islands/ballot/BallotCard.tsx:26`, `src/islands/ballot/BallotCard.tsx:29`).
   - 공식 의사결정 용도에는 별도 1회용 ballot capability가 필요하다는 중단 조건을 readiness 계약에 남겼다.

4. 오프라인·재접속 데이터 보존
   - 오프라인 초안은 토큰·접속코드를 포함하지 않는 큐에 저장하고, 재접속 뒤 동일 request ID와 base version으로 재전송한다.
   - 새 꼭지 개방 시 기존 입력·포커스·스크롤을 보존하고, 충돌 시 서버 snapshot을 덮어쓰지 않고 사용자에게 복구 경로를 제공한다.
   - 서버 로그아웃이 실패하면 로컬 capability를 지우지 않아 재시도할 수 있게 했다.

5. 릴리스 증거 결박
   - release validator는 40자리 source commit, 현재 checkout의 ancestor 관계, 이후 변경이 허용된 evidence 파일뿐인지 확인한다 (`scripts/verify-0912-release-report.mjs:647`).
   - 자동 접근성 보고서는 깨끗한 source와 정확한 revision이 일치할 때만 release evidence로 표시한다 (`automation/platform-accessibility-audit.mjs:2104`).
   - 생성될 결과 보고서를 선행 입력으로 요구하던 추적성 순환 의존과 `/b`의 오래된 기대 문구를 제거했다.
