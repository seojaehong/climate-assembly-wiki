# 7.4 최종결정 온톨로지 반영 감사

## 결론

운영규정 최종 결정은 기존 `regulation-2026-06-13.json`에 이미 상당 부분 반영되어 있었다. 이번 작업에서는 그중 최종 결정에 해당하는 노드와 표결 근거, 토론 맥락 노드를 따로 묶어 `final-regulation-decisions-0704.json` 세트로 분리했다.

의제 선정은 기존 `workshop-2026-06-13.json`에 후보별 논의 맥락이 들어 있었고, 7.4 투표 결과는 `public/agenda-vote-0704/data.json`에 별도로 있었다. 그러나 “PPT 결론 + 투표 결과 + 기존 논의 맥락”이 하나의 온톨로지 세트로 묶인 상태는 아니었다. 이번 작업에서 이를 `final-agenda-decisions-0704.json`으로 새로 만들었다.

## 운영규정 반영 상태

최종 발표 시나리오가 말하는 운영규정 결정은 다음 흐름으로 기존 그래프와 연결된다.

| 결정 | 반영 상태 | 맥락 신호 |
| --- | --- | --- |
| 기획참여단 의결정족수 = 출석 2/3 | 기존 그래프에 결정 노드 있음 | 중간 |
| 숙의참여단 분과 구성 = 분과를 둠 | 기존 그래프에 결정 노드 있음 | 약함 |
| 분과 개수 = 감축1·감축2·적응 3개 | 기존 그래프에 결정 노드 있음 | 약함 |
| 숙의참여단 분과 의결정족수 = 출석 2/3 | 기존 그래프에 결정 노드 있음 | 약함 |
| 숙의참여단 전체 의결정족수 = 출석 2/3 | 기존 그래프에 결정 노드 있음 | 약함 |
| 제14조 제1항 = 직·간접 관련으로 확장 | 기존 그래프에 결정·토론 맥락 있음 | 중간 |
| 제14조 제3항 = 시민의 삶·일상 실천 유지 | 기존 그래프에 결정 노드 있음 | 약함 |

운영규정은 “결론 자체”는 이미 반영되어 있었다고 볼 수 있다. 다만 원래 그래프는 전체 운영규정 구조와 토론을 넓게 보여주는 형태라, 최종 발표 결론만 따로 보기에는 불편했다. 새 세트는 이 최종 발표용 경로를 좁게 만든 것이다.

## 의제 반영 상태

의제 후보들은 기존 워크숍 그래프에 실제 논의 흔적이 있었다. 특히 다음 후보들은 논의 맥락이 강하게 잡혔다.

| 의제 | 현재 처리 | 맥락 신호 |
| --- | --- | --- |
| 생애주기 탄소중립 교육 및 시민의식 개선 | 발표 시나리오상 선정·통합 결론 | 강함 |
| 자원순환·생활폐기물 감축 | 발표 시나리오상 선정 결론 | 강함 |
| 시민의식 개선 및 참여 활성화 | 독립 후보였으나 교육 의제에 통합 | 강함 |
| 대중교통 친환경 교통전환 | 후보로 논의됨 | 강함 |
| 친환경 도시 인프라·에너지 전환 및 기후위기 적응 | 후보로 논의됨 | 중간 |
| 기후재정 확보와 지자체 자발적 참여 | 후보로 논의됨 | 강함 |
| 시민참여 기반 기후 거버넌스 강화 | 후보로 논의됨 | 중간 |
| 에너지 절약 및 온실가스 배출 감축 | 후보로 논의됨 | 중간 |

따라서 “이게 대화상 맥락상 선정 가능성이 있었나?”라는 질문에는, 현재 데이터 기준으로는 “있었다”고 보는 편이 맞다. 다만 최종 선정 여부는 후보별 논의량만으로 판단하면 안 되고, 7.4 투표 결과와 발표 시나리오의 통합·선정 로직을 함께 봐야 한다.

## 주의할 점

`20260704_의제선정결과_v6.pptx`의 형제 파일인 발표시나리오에는 `7.4 당일 확정 후 수정` 표시가 남아 있다. 특히 감축2 “새로운 의제” 슬롯은 현재 repo에 있는 증거만으로는 별도 최종 의제로 확정됐다고 단정할 수 없다.

또한 `public/0704-admin/decision-votes-report.json`의 V0/V1A/V1B 조건부 투표는 현재 응답 수가 모두 0으로 기록되어 있다. 그래서 조건부 투표 결과를 최종 결론 근거로 사용하지 않았다.

PPT 텍스트는 `markitdown`으로 추출했지만 한글이 깨져 나왔다. 따라서 읽을 수 있는 발표자료 텍스트 근거는 같은 폴더의 발표시나리오 Markdown을 사용했고, PPT 파일은 원본 발표자료 경로로 함께 보존했다.
